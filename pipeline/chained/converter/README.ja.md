# converter — ステートレス JSON→JSON 変換

> 日本語版 — English: [README.md](README.md)

ConvertFlow ステップの契約: `Converter` インターフェースとサブセット出力検証。
すべての実装はステートレス — 同一入力は常に同一出力を返す。

## Converter インターフェース

```go
type Converter interface {
    Convert(ctx context.Context, data []byte) ([]byte, error)
}
```

nil でない error はステップ自体の失敗を意味する（プロセッサ層では `contract.StatusErrored` にマップ）。
Converter はフィルタリングを行わない。通過／破棄の判断はフィルターステップに属する。

`Convert` は並行呼び出しに対して安全でなければならない。

## 2 つの JSONata モード（jsonata/ サブパッケージ）

### 全ドキュメントモード — `New(expr string)`

式は入力ドキュメント全体を評価コンテキストとして受け取り、その結果が出力ドキュメントになる。
フィールドのリネーム、射影、新規フィールドのゼロからの計算など、ドキュメントの再整形に適している。

### フィールド別ステップモード — `NewSteps(steps []FieldStep)`

各ステップはひとつ前のステップが生成したドキュメント（ステップ 0 の場合は元の入力）に対して式を評価し、
結果を指定した最上位フィールドに書き込む。ステップは順次合成される: ステップ N はステップ N-1 の
出力を読む。例: ステップ 1 が `full = firstName & " " & lastName` を計算し、ステップ 2 が
`$.full` を読んで挨拶文を生成する。

**フィールド検証**: 各 `FieldStep.Field` は空であってはならない。空のフィールド名を持つステップがある場合、
`NewSteps` は構築時にエラーを返す。

どちらのモードも構築時にすべての式をコンパイル済みにする。
空の式 / 空のステップスライス → 構築エラー。不正な構文 → 構築エラー。
起動時に失敗し、ランタイムでは失敗しない。

## 合成ルール（ステップモード）

ステップはドキュメントを順番にミューテートする。各ステップは前のステップが書いた
すべてのフィールドを参照できる。最終ドキュメント（元のフィールド + ステップが追加したフィールド）が
出力としてマーシャルされる。

## ValidateSubset

```go
func ValidateSubset(doc []byte, required []string) error
```

JSON オブジェクトが `required` に列挙されたすべての最上位フィールドを含むかどうかを確認する。
ドット区切りパスは **サポートしない**; 各要素は単純な最上位キーでなければならない。
最初に見つかった欠落フィールドの名前を含むエラーを返す。
`required` が空またはすべてのフィールドが存在する場合は nil を返す。
変換後にイベントを転送する前の出力バリデーションを意図している。

プロトコル境界のハードルール（`canon.StrictDecoder` を通じたデコード）に従う。

## 厳格な入力デコード

`Convert` は `canon.StrictDecoder` を使って入力をデコードする。以下を強制する:

- **末尾データの拒否**: ドキュメントは正確に 1 つの JSON 値でなければならない。`{"a":1} {"b":2}` → エラー。
- **重複キーの拒否**（RFC 8785 §3.2.5）: `{"a":1,"a":2}` → エラー。
- **`json.Number` による数値精度の保持**。

これにより、署名済み `outputHash` にハッシュされるバイト列と実際にデコードされたバイト列が一致することを保証する —
入力が暗黙的に変換されることはない。

## 数値モデル

厳格デコード後、`json.Number` 値は jsonata-go に渡す前に正規化される:

| 値のカテゴリ | Go 型 | 備考 |
| --- | --- | --- |
| 整数値、int64 に収まる | `int64` | 2^53 を超える整数も含め、同一性が正確に保持される |
| 小数、指数表記、または int64 を超える整数 | `float64` | 2^53 を超える値では精度が失われる可能性がある |

算術演算子（`+`、`-`、`*`、`/`）および比較演算子（`>`、`<`、`=` など）はネイティブ Go 型で動作するため、
`{"next": $.age + 1}` や `$.age > 18` のような式が正しく機能する。

**整数同一性の注意点**: 2^53 を超える整数を含む算術演算は内部的に float64 で動作し、float64 の境界で
精度が失われる。フィールドアクセスパス（`$`、`$.field`）は int64 を正確に保持する。

**ゴールデンテスト結果**: 入力 `{"n": 9007199254740993}`、式 `$`、
出力 `{"n":9007199254740993}`（int64 同一性により精度保持）。
標準 `json.Unmarshal`（float64）では出力が `{"n":9007199254740992}` になる（精度損失）。

## エラー契約

| 条件 | エラー発生箇所 |
| --- | --- |
| 空の式 / 空のステップスライス | `New` / `NewSteps`（構築時） |
| 空の `FieldStep.Field` | `NewSteps`（構築時） |
| 不正な JSONata 構文 | `New` / `NewSteps`（構築時） |
| 不正な JSON 入力（末尾データ・重複キーを含む） | `Convert` |
| 全ドキュメント式が undefined を返す | `Convert` |
| フィールド別ステップ式が undefined を返す | `Convert`（ステップ番号とフィールド名を含む） |
| JSONata 評価エラー | `Convert` |
