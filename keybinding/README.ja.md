# keybinding — 鍵の結び付けと失効の一覧
> 日本語版 — English: [README.md](README.md)

**鍵の結び付け**は、発行者が「この鍵は、この主体（種類、役割、鍵の種類）のもので、この受け手のために、この期間、失効の一覧のこの番号で」と述べる credential である。受け手は、発行者の信頼の起点と、前もって持っている失効の一覧で確かめ、判定の時に発行者に問い合わせない。

- `Issue` は `Binding` を `KeyBindingCredential`（W3C VC Data Model 2.0、eddsa-jcs-2022）として署名する。`IssueStatusList` は、発行者の失効の一覧を W3C の `BitstringStatusListCredential` として署名する。印を付けた番号は、同じ id の後の一覧でも印のままにし、別の結び付けに使わない。
- `Verifier.VerifyStatusList` は一覧を確かめ、与えた時刻で新しいものを返す。一覧は戻らない（`validFrom` が古いもの、同じで中身が違うものは断る。中身は圧縮を除いて、展開したビットとほかのすべての欄で比べるので、同じ一覧を別に圧縮したものは同じ一覧）。新しい一覧は、持っている一覧の印を消さない（失効は取り消せない。短い一覧で、その終わりより先にある印は消えたものとみなす）。未来の日付の一覧は取らない。一覧の id は発行者の DID URL。確かめた `StatusList` は変えられず、署名した鍵が起点の発行の鍵にある間だけ効く（判定にも、持っている一覧としても）。持っている一覧がなければ、新しい一覧なら何でも受け付ける。
- `Verifier.RestoreStatusList` は、再起動の後に、受け手が最後に持っていた生の一覧から、持っている一覧を戻す（それより古い一覧を戻すと、下限が下がる）。`VerifyStatusList` と同じく確かめ、与えた時刻より後の日付でないことも確かめるが、古さも `validUntil` も見ない。鮮度の窓を過ぎても、一覧は「どの印が立っていたか」の発行者の言葉なので、新しい一覧が守る印の下限になる。`VerifyBinding` は、ほかの一覧と同じく、新しい間だけこれを使う。署名した鍵が起点から外れた一覧は戻さない（`ErrSignature`）。鍵が外れた理由が漏えいなら、その印は信じられないため。その時は持っている一覧がなく、次の一覧を、前に見た印と比べない。どの鍵が効くかは起点が決める。`ErrSignatureUnestablished` や context の誤りは、後で戻し直す。戻すまでは、持っている一覧なしで新しい一覧を確かめない。
- `Verifier.VerifyBinding` は順に確かめる: 起点の発行者が発行の鍵で、W3C の eddsa-jcs-2022 の契約で署名した。形が正しく、安全な範囲の外の数がない。時刻が期間の中で、期間が起点の上限の中。持っている一覧が発行者のもので、新しく、印がない。この受け手あて。

wire の書き方は 1 つ: 時刻は UTC で秒まで、一覧の番号は 10 進の文字列（JSON の数は、2 つの値が同じ正規形になりうるので使わない）、`roles` は重ならない名前の列、鍵は `keyId` と、`kty` ごとに RFC 7638 が hash する欄だけを持つ公開の JWK（Ed25519、P-256、RSA で、`crypto` の検査が受け付ける鍵）。

今は確かめられない署名（発行者の文書が読めない）は `ErrSignatureUnestablished` で、`ErrSignature` ではない。偽物とせず、やり直す。

ここにないもの: 発行者が何を結んでよいか（範囲の中の種類、役割、鍵の種類）と、鍵と署名の照合。どちらも呼ぶ側の務めで、`Binding` が要るものを運ぶ。
