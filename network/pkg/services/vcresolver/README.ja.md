# vcresolver — プロベナンスチェーン解決
> 日本語版 — English: [README.md](README.md)

パイプラインランタイムが送信した VC を保存し、監査のためにレジストリ境界を越えて `previousCredential` チェーンを解決する。

## 動作

- `StoreVC` は VC を（JCS SHA-256 ハッシュをキーとして）保存し、未保持であれば `previousCredential` を未解決キューに追加する。
- バックグラウンドのバッチリゾルバーが定期的に未解決プールを消化し、アップストリームレジストリエンドポイント（ConnectRPC）から VC をフェッチして、成功時にチェーンを再帰的に処理する。リトライ上限あり、接続エラー時のみ追加レジストリへのフォールバックあり。
- 呼び出し元が指定したエンドポイントおよびドキュメント由来のアップストリームエンドポイントは、アウトバウンド呼び出し前に SSRF ガードを通過する。

## PoC 実装状況

本番配線（`cmd/network`）は VC ストアと未解決プールをノードの data-dir 配下のファイルベース `vcfilestore` で永続化する。インメモリ実装はテスト・組み込み用途として残る。すべてのバッチチューニングパラメーターは `reference.conf` から取得する（Go 側のデフォルト値なし; 非正数のオーバーライドはスタートアップを失敗させる）。

**監査義務**: 事後監査モデルは VC body が監査期間にわたり解決可能であることを要求する。ファイルベースストアは単一ノードではこれを満たす。トランザクショナルな保証は `tlog` ベースの基盤に実装される。in-memory 運用は開発専用であり、監査可能性を主張する deployment では決して使わない。
