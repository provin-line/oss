# network/pkg/services — サービスパッケージ
> 日本語版 — English: [README.md](README.md)

ネットワークサービスごとに 1 パッケージ。すべてのサービスは同じ三層構造に従う:

```
<service>/
├── handler/            proto ↔ ドメイン変換 + Connect エラーマッピング。ロジックなし。
├── <service>.go        ドメインサービス。proto 型なし。コンストラクター: New(required..., opts ...Option)
└── store/              永続化インターフェース + yamlstore/ 実装。バリデーションなし。
```

## 横断的ルール

- **型付きエラーをエンドツーエンドで使用。** ドメインエラーはセンチネル/型付きエラーとして定義し、ハンドラー内で `errors.Is` を使って Connect コードにマッピングする。エラーメッセージの文字列マッチング（前身 PoC での近道）はここでは許容しない。
- すべてのハンドラーおよびストア実装にコンパイル時適合性アサーション（`var _ Iface = (*Impl)(nil)`）を記述する。
- セキュリティクリティカルなパスではフェイルファストなコンストラクターを採用: 設定ミスのあるバイナリは最初のリクエスト時ではなく、スタートアップ時に落ちなければならない。
- ストア実装がファイルシステムパスを構築する際は、安全性チェック済みの DID/名前セグメントのみを使用する（パストラバーサルガードはカリーにではなく境界部分に置く）。

## Services

| Package | Notes |
|---|---|
| `didregistry/` | DID ライフサイクル; YAML の DID/鍵ストアを所有 |
| `signer/` | `keystore` 経由の署名; 独自ストアなし |
| `schemaregistry/` | イミュータブルスキーマ; コンテンツアドレス指定のバージョン命名 |
| `chainmanager/` | サブスクリプション、許可リスト、インフラオペレーター、L2 wireauth |
| `vcresolver/` | VC ストア + 非同期バッチチェーン解決 |
