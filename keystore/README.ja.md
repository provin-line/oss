# keystore — 秘密鍵ストレージコントラクト
> 日本語版 — English: [README.md](README.md)

`KeyStore` インターフェース: レジストリが保持する秘密鍵の永続化（鍵ペアの保存・秘密鍵の取得・鍵の削除。DID + キー ID でアドレス指定）。

## トップレベルパッケージとして独立させる理由

前バージョンのコードベースでは、このインターフェースは DID レジストリのストアパッケージ内に存在しており、署名サービスが他のサービスの内部をインポートせざるを得なかった。鍵の管理は独自のコントラクトである — DID レジストリ（発行時の鍵生成）と署名サービス（署名）の両方が依存する KMS モデル境界であり、将来的に Vault・HSM・クラウド KMS バックエンドが接続される継ぎ目でもある。

## 規約

- キー ID は論理的な名称（`auth`・`signing`）であり、DID Document フラグメント（`#auth`・`#signing`）に対応する。
- 実装は制限的なパーミッション（YAML バックエンドではファイルモード 0600）で秘密鍵を保存し、安全性チェック済みの DID セグメントのみからストレージパスを構築する。
- 実装はそれぞれのサービスと同居する（例: レジストリの YAML ストア）。このパッケージが所有するのはコントラクトのみである。
