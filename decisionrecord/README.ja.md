# decisionrecord — 判定ごとの記録
> 日本語版 — English: [README.md](README.md)

判定する部品（関門、境界の段、配送の判定）は、判定ごとに `Record` を 1 つ出す。中身は、判定の ID、判定した部品、時刻、結果、拒否した検査と理由、判定が帰属する主体、判定の対象の content address、部品ごとの欄である。中身の値（payload）は持たない。

`Filter` は、明示して選んだ水準で、記録を `Sink` に書く。

| 水準 | 書くもの | 記録が書けないとき |
| --- | --- | --- |
| `all` | すべての記録 | error を返す。判定する部品は判定を拒否に倒す |
| `refusals` | 拒否と unenforced の判定だけ | 警告。判定は変えない |
| `summary` | `Flush` ごとに、部品ごとの `Summary`（結果と検査ごとの数） | 警告 |
| `none` | 何も書かない | — |

ゼロ値の水準は断るので、水準は選んだときだけ効く。判定する部品の決まりは 1 つだけ:「`Filter.Record` が error を返したら拒否する」。`all` より下の水準では、記録が書けなくても判定は変わらないので、unenforced の判定は記録なしで先へ進む。記録なしで進めてはならない部品は `all` を選ぶ。形の誤った記録（`Record.Validate`）は、`none` を含むどの水準でも error になる。書き出し先の誤りではなく、書いた側の誤りだからである。ここの書き出し先は、書き出し先に直に書く呼び手のために、記録と要約（`Summary.Validate`）も確かめる。

結果は 3 つある。`accepted`（どの検査も拒否せず、判定の対象は先へ進んだ）、`refused`（止める検査が拒否し、対象は進まなかった）、`unenforced`（拒否したのが、止めずに記録だけする検査だけだったので、対象は進んだ）。

受け入れとして記録した後に拒否した判定は、同じ `DecisionID` でもう一度記録する。判定の結果は、読む順によらず、その ID の記録のうち一番強いものとする。記録の**どれか**が拒否なら拒否、そうでなく unenforced があれば unenforced、どちらも無ければ受け入れ。書く側は、1 つの判定を受け入れとして何回でも記録し、その後に unenforced か拒否のどちらかを高々 1 回だけ記録し、その後は何も記録しない（書く側は、書くときに結果を知っている）。1 つの判定の記録は前の記録が受け取られてから書く。そうすれば要約の水準は判定を 1 回ずつ数える。要約の水準が覚える ID は受け入れた判定の分だけなので、memory は判定する部品が認めた分で抑えられ、誰でも起こせる拒否や unenforced では増えない。ほかの拒否と unenforced は来たときに数える。この決まりを破ると、要約が判定を 2 回以上数えるか、その結果の最初の記録の検査で数えるだけで、記録のうち一番強い結果より弱い結果では数えない。ほかは何も変わらない。数は結果と検査ごとに持ち、検査は判定する部品が決めた固定の名前である。拒否と unenforced には拒否した検査を書き、受け入れには書かない。`Evidence` は役割と content address（`contentaddress.Address`）の順序つきの列で、値は入れない。主体は、ID、判定した部品と同じく、空でない正しい UTF-8 でなければならない（読む側が key にするため）。時刻は 0000〜9999 年。人が読む文字列（理由、属性の値）は、正しくない UTF-8 を置き換えて書くので、記録が自分の bytes で失われない。要約の数は 0 から 2^53−1（`int64`）で、JSON の数で書き、結果、検査の順に、どちらも文字列として比べて並べ（結果は `accepted`、`refused`、`unenforced` の順）、重ねない。

書き出し先は並行に使えなければならず、`all` の水準では、記録が残ってから nil を返す（buffer しない writer か、sync した writer）。

- `NewJSONLines`: 1 行に RFC 8785 の JSON を 1 つ。`"v"`（形の版）と `"kind"` を持つ。時刻は UTC で小数 9 桁なので、文字列のまま並べられる。行は `"\n"` だけで分ける（U+2028 と U+2029 はそのまま書く）。書けなかった後の行は、新しい行から始める。
- `NewLog`: 記録か要約ごとに構造化ログを 1 件。handler を通すので、info を取らない logger や、失敗した handler は error になる。残さずに nil を返す handler は見分けられないので、`all` では nil が「残した」を意味する handler を使う。

`NewFilter` で作っていない `Filter` は、すべての呼び出しを断る。この package は、関門が送り直しを断るために持つ使い済みの nonce の記録ではない。
